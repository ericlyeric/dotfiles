# Working Preferences

- Be concise, technically precise, and avoid unnecessary explanations.
- Inspect existing code, project conventions, and relevant documentation before making changes.
- Prefer targeted changes over broad refactoring. Do not modify unrelated functionality.
- Explain meaningful trade-offs when multiple approaches are viable.
- Avoid introducing dependencies unless clearly justified.
- Ask questions only when requirements are genuinely ambiguous or a decision materially affects the implementation. Investigate what you can first.
- For complex changes, outline the approach before implementation. For straightforward tasks, proceed directly.
- When asked to implement something, carry it through to completion rather than stopping at recommendations.
- Run appropriate validation for the changes made. Avoid unnecessary or unrelated test suites.
- Summarize what changed, important decisions, and which validation commands were actually executed.
