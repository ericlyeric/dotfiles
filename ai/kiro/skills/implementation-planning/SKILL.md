# Implementation Planning

For complex changes, understand the problem and establish an implementation plan before coding.

## Workflow

1. **Understand:** Identify requirements, expected behaviour, constraints, and acceptance criteria.
2. **Explore:** Inspect relevant code, architecture, dependencies, and existing patterns.
3. **Evaluate:** Consider approaches, trade-offs, risks, and downstream impacts.
4. **Plan:** Define ordered implementation steps, affected components, and dependencies.
5. **Validate:** Identify required tests and verification steps.

## Guidelines

- Prefer existing patterns and avoid unnecessary complexity or scope expansion.
- Consider integration points and backward compatibility.
- Highlight assumptions, risks, and unresolved decisions.
- Keep planning proportional to task complexity.
- Skip formal planning for straightforward changes.
- When asked to implement, follow the plan rather than stopping at recommendations.

## Output

For complex changes, include the proposed approach, implementation steps, affected areas, testing strategy, and important risks.
